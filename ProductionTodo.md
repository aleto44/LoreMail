## 1. Cloudflare KV Namespace

`apps/worker/wrangler.toml` has placeholder IDs that must be replaced before `wrangler deploy` will work.

```bash
# Create the namespace
wrangler kv namespace create LOREMAIL

# For the preview / local dev environment
wrangler kv namespace create LOREMAIL --preview
```

Update `wrangler.toml` with the IDs printed by those commands:

```toml
[[kv_namespaces]]
binding = "KV"
id = "PASTE_PRODUCTION_ID_HERE"
preview_id = "PASTE_PREVIEW_ID_HERE"
```

## 2. Deploy the Worker

```bash
cd apps/worker
wrangler deploy
```

After deploying, set the production vars either via `wrangler.toml` `[env.production]` or the Cloudflare dashboard:

| Variable      | Value                                       |
|---------------|---------------------------------------------|
| `ENVIRONMENT` | `production`                                |
| `PWA_URL`     | Production PWA URL (see section 3 below)    |

> The `[vars]` block in `wrangler.toml` is for local dev only. Production vars belong in the Cloudflare dashboard → Worker → Settings → Variables, or in a `[env.production.vars]` block.

## 3. Hosting the PWA on GitHub Pages

The PWA is a Vite + React SPA with **no client-side router** (navigation is state-based), so GitHub Pages works without any SPA redirect hacks.

### Steps

1. **Set the base path** in `apps/pwa/vite.config.js`:

   ```js
   base: '/loremail/',   // or '/' if deploying to a custom domain
   ```

2. **Set the worker URL** at build time. In `apps/pwa/.env.production`:

   ```
   VITE_WORKER_URL=https://loremail-worker.<your-subdomain>.workers.dev
   ```

3. **Add a GitHub Actions workflow** at `.github/workflows/deploy-pwa.yml` (in the LoreMail source repo — not the game repos):

   ```yaml
   name: Deploy PWA
   on:
     push:
       branches: [main]
       paths: ['apps/pwa/**']
   jobs:
     deploy:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with: { node-version: 20 }
         - run: npm ci
         - run: npm run build --workspace=apps/pwa
         - uses: peaceiris/actions-gh-pages@v4
           with:
             github_token: ${{ secrets.GITHUB_TOKEN }}
             publish_dir: apps/pwa/dist
   ```

4. In GitHub repo Settings → Pages, set **Source** to the `gh-pages` branch, root folder `/`.

The PWA URL will be `https://<your-github-username>.github.io/loremail/` (or `/` if using a custom domain).

## 4. Hosting the Launcher on GitHub Pages

**Yes, the Launcher can also be hosted on GitHub Pages** — it is a plain Vite SPA (no React Router, no SSR, no server-side logic). It communicates with the Cloudflare Worker via `fetch`, so all it needs is a static file host.

### Options

| Option | Recommendation |
|--------|----------------|
| Same repo, different path (`/launch/`) | Simple if both apps live in the same GitHub repo |
| Separate GitHub repo → separate Pages site | Cleaner separation; independent deploy pipeline |
| Netlify / Vercel | Drop-in alternative if Pages causes trouble |

### Steps (same-repo approach)

1. **Set the base path** in `apps/launcher/vite.config.js`:

   ```js
   base: '/launch/',
   ```

2. **Set the worker URL** in `apps/launcher/.env.production`:

   ```
   VITE_WORKER_URL=https://loremail-worker.<your-subdomain>.workers.dev
   ```

3. **Add `.env.production` reads** to `apps/launcher/src/main.js` — currently the worker URL is looked up via `import.meta.env.VITE_WORKER_URL`. Confirm it is used consistently.

4. Extend the deploy workflow above to also build and publish `apps/launcher/dist` to a `/launch/` sub-path (or add a second workflow).

## 8. Engine Files Sync

`apps/worker/src/lib/engine-files.js` contains the entire GM engine embedded as strings. After any change to `packages/gm-engine/src/`, run:

```bash
node scripts/generate-engine-files.mjs
```

This regenerates `engine-files.js`. Commit the result before deploying the worker.

## 9. (Optional) Custom Domain

Point a custom domain (e.g. `loremail.app`) to the GitHub Pages site via a `CNAME` record. Update `PWA_URL` in the worker accordingly. Update `base: '/'` in `vite.config.js` since the app will be served from the root.
